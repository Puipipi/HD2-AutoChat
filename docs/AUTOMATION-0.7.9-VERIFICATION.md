# 0.7.9 主客机预设与本地输出

日期：2026-10-09。游戏目标仍为Steam build 25480438；游戏未运行，本版没有实机发送验收。

## 行为

- 右上方“主机预设 / 客机预设”选择编辑对象。会话API确认的当前角色选择实际使用对象；编辑另一套不改变正在运行的选项或队列。
- 欢迎、标记开关及模板、冷却、角色范围、无人房间策略、总开关与输出均分开保存。定时任务分角色显示和执行，两套合计32个；切换角色不重置截止时间。
- 旧扁平设置迁移为主机；客机复制旧标记偏好和模板，默认关闭欢迎、scope=all、output=local。旧任务及旧单任务计时器归主机，不复制到客机。新安装主机欢迎保持原来的默认关闭。
- 设置v3使用`host.KEY`/`client.KEY`，仅解析数据并逐项验证，原子保存成功后才提交。任务旧9列格式继续可读，第10列保存host/client；缺省为host。
- 切换角色清除旧欢迎/标记队列、去重与冷却。身份未确认时不自动输出；有预期角色的旧消息在发送前再次核对，身份变化拒绝。
- 小队公屏走原发送入口；仅自己可见走本地add-line，覆盖欢迎、ping、召唤/任务执行、定时任务、旧计时命令和注册模组API。控制台显式send/force仍为手动小队发送。
- 本地签名失败不会回退公屏。定时任务在本地预检失败时不消耗一次性任务，等待重试；接口返回失败，由调用模组决定重试。
- 本地消息仍使用游戏普通聊天姓名格式，未实现无姓名系统广播。文字聊天开关及所选预设策略继续生效。

## 原生来源

对照此前只读取得的当前build内存代码和BetterChat作者研究笔记，独立核对：

| 入口 | RVA | 用途 |
| --- | --- | --- |
| 原有send | `0x1097560` | 组装并发送普通聊天，再加入本机记录 |
| 新增add-line | `0x10979C0` | 向指定chat对象加入聊天记录，然后通知本机HUD |
| 本机HUD chat notice | `0x12F2F60` | 查发送者姓名和颜色，使用普通聊天格式显示 |

add-line的ABI为`void(uint64_t chat, uint64_t sender, const char* text)`；由原发送函数及接收处理路径调用。
其末尾`0x1097C65`调用HUD notice，`0x1097C8C`返回；本版不调用该路径以外的发送器，也不修改机器码。
函数体含平台过滤等间接调用；这里只把该函数作为已观察到的本地聊天入口，没有将“没有直接RPC call”单独当作多人不可见的实测证据。

入口28字节签名，终止于完整的chat-disabled条件跳转：

`40 57 41 55 41 56 48 83 EC 40 80 39 00 4D 8B E8 4C 8B F2 48 8B F9 0F 84 A7 02 00 00`

保留原有5项发送签名门禁，本地入口另行核对，失败只拒绝本地输出。sender从当前context+0xB398读取原始8字节，复制到uint64数组，不转为Lua double。
文本按UTF-8边界截断至512字节，加NUL后交原生入口。不打开聊天输入框，不代其他玩家发送。
