# AutoChat 0.8.0 verification record

Prepared 2026-10-09 for the 0.8.0 release candidate. The game was not running during this verification work. This record separates reproducible offline evidence from checks that still require loading the release in game.

## Release behavior covered

- Stratagem settings use stable IDs and are grouped only when both native name keys and call type match. The current raw catalog has 149 valid records and yields 135 visible settings groups. Same-name variants share the group rule; the representative ID is a persistence key and does not identify which variant was actually called. A later catalog update can select a different representative, so inspect group settings after such an update.
- Icons use the catalog's material hash and are drawn only after `can_get('material', ...)` reports that the material is loaded. Missing materials leave the text entry available.
- Enemy size comes from the game's `UnitSize` enum (`Small`, `Medium`, `Large`, `Massive`), not armor power or threat level. Flight is a separate component-based classification which takes priority over size. The reviewed data contains 142 spottable hostile resources, including 12 flying resources; friendlies and non-spottable entries are excluded from the live alert list.
- Fine-grained alert settings support per-rule enablement, separate mark/call templates, inherited cooldown, explicit zero cooldown, and per-triggering-player rule timers. The 500 kg Eagle strike and Orbital Napalm Barrage receive explicit zero-second rules only during the first migration to settings v4. Later resets remove overrides and restore the global timer. Zero cooldown retains event deduplication and master, role, session, and output policy checks; urgent alerts do not bypass those checks.
- The named preset library stores up to 32 entries. Each entry captures automation options and fine-grained rules for the selected host or client profile. Scheduled tasks remain separate. `.autochat` files are bounded UTF-8 data, validated field by field, and never evaluated as Lua. Writes use a temporary file and atomic replacement. A corrupt library is reported and its existing bytes are left untouched rather than replaced with an empty library.

## Manual game checks still required

The game was not running, so this candidate has no 0.8.0 runtime verification. After installation, check the supported game build and loader startup first. Then verify the settings panel opens, loaded native material icons render, and an unloaded icon leaves its row usable. Exercise a normal and a shared-name stratagem variant, including summon and execution events, to confirm the expected group settings, trigger timing, and deduplication. Check enemy size and flight routing with spottable targets, including a flying target whose `UnitSize` is not Small.

For each selected role, create and replace a named preset; export and import a `.autochat` file while the preset menu is open. Confirm import adds a library entry without changing the active profile, and that explicitly applying the selected entry updates only the selected role's automation options and fine-grained rules while preserving scheduled tasks. Check Chinese and multiline templates and malformed or oversized file rejection using the UI. Do not corrupt the live preference library for this check; corruption handling is covered by offline tests. Finally check actual message appearance and delivery policy with host and client profiles in a multiplayer session.

These checks require the game and appropriate targets or a second player. The game was not running during this work. Actual game startup, native throw timing, loaded icon appearance, message appearance, multiplayer delivery, and client privacy behavior remain unverified. Offline tests and previews cannot establish those results.
