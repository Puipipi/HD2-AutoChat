# 多人投递验证成功 — 2026-10-08

**结论：AutoChat 发的聊天消息，同小队的另一名玩家（另一台机器、另一个人）看到了。**

这是本模组最后一块缺失的证据。此前"游戏接受了消息"已经证实，但"**别人也看得见**"
一直没有验证过，因为本机长期只有一个玩家。

- 本机 = **先当主机**（host），对方 = 客机（client），另一台机器、另一个人
- 随后**交换角色**：本机 = **客机**，对方 = 主机
- 游戏 build 25480438
- AutoChat 0.2.7（含 30 倍性能修复）

## `PEER_COUNT` 在两种角色下都读到 0（但枚举找得到人）

这是本次会话最值得记的一个观测。

模组日志里**每一次** `peer count` 读数都是 **0** —— 包括本机当主机时、以及本机当
客机时。最后一条停在 `12:47:11` 的 `0`。

但同期，`other_peers()`（枚举 `ctx+0x16398` 的槽位、与自己 id 比较）**20 次**
都算出了 **1**，并据此正确放行发送（日志里 `to 1 other player(s)` 共 20 行）。

结论：**`ctx+0x16390`（`PEER_COUNT`）不是"会话里有多少人"。** 在主机与客机两种
角色下、当会话里确实有 1 名对端时，它都读 0。

- 发送守卫实际依据的是 **`other_peers()` 的枚举结果**，不是这个字段 —— 这也是
  它能正常工作、没有被这个字段误导的原因。
- **不要用 `PEER_COUNT` 判断"会话里有没有人"。** 它在主机和客机上都可能为 0。
- 此前 README 里我曾写过"主机侧 `PEER_COUNT` 为 0"——现在有第二次观测（客机侧
  也为 0），这条从"单次观测"升级为**两种角色下都复现**。

（`M.LOCAL` 只比较低 32 位，参考模组比较完整 u64。两种角色下都没出问题，但这个
简化仍然没有被单独验证过。）

## 未验证

- **"目标 -1 = 广播给所有对等端"仍是照抄参考模组的说法。** 我确认发送函数入口
  有一条 `mov edx, 0xffffffff` 紧跟一次 `call`，但那个 callee 落在
  `.winlice` / `.vm_sec` 虚拟化节上，**无法可靠静态追踪**。指令看到了，含义没追证。
- **只测过 1 名对端。** 3–4 人小队未测，"所有对等端"里的"多"这一层没测到。
- 第一轮里出现的两次 history 跳号（`0/11 → 0/12`、`0/13 → 0/14`）原因未确认；
  最可能是对方也在发消息，但用户没有确认，**不作为结论**。
- 发送瞬间键鼠是否不受影响：帧率无抖动、模组不声明任何输入符号，但没有做键盘级实测。
- 聊天开关语义、`send` 第二参数含义、环形读取器的 entry 基准地址 —— 见
  [LIVE-EVIDENCE-2026-10-08.md](LIVE-EVIDENCE-2026-10-08.md) 的未验证清单。
