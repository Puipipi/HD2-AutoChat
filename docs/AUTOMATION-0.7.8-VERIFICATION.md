# AutoChat 0.7.8 — 任务战备与撤离目标

## 修复与显示

- 现场撤离信标、鹈鹕飞船使用具体实体名；地图撤离图钉继续显示“撤离区”。新增另一版信标、任务货运车、机械虫洞与鹈鹕资源变体。当前目录220个资源，184个具体名称，36个只有通用任务交互物身份，数量不代表220种任务或全部实机验收。
- 非投掷的任务战备从游戏成功使用记录读取，补齐超级地球旗帜等召唤。没有生成物品的调用，如上传数据，使用独立模板 `{玩家名}正在开始{目标}`。
- “战备召唤 / 任务执行”控制两类调用；“战备物品标记”控制手动标记，两者独立。任务执行模板可编辑、持久保存，支持已有玩家变量及 `{目标}/{动作}`；动作分别为召唤、开始、标记。
- 共享战备会把同一次成功记录同步到多名玩家。相同战备ID与成功时间只发一次；无法证明调用者时使用“小队”，不冒充本机或某个队友。能确认调用者的事件继续使用其名字、缩写与颜色。

## Wiki 对照与实体依据

核对 [Wiki任务目录](https://helldivers.wiki.gg/wiki/Objectives)、[撤离区](https://helldivers.wiki.gg/wiki/Extraction_Zone)、[撤离飞船](https://helldivers.wiki.gg/wiki/Extraction_Shuttle) 和 [撤离流程](https://helldivers.wiki.gg/zh/wiki/Extraction)。Wiki区分地点、终端与飞船；它的任务类别用于查漏，不能替代实体ID。页面直读部分返回403，本轮使用可检索正文摘要；资源身份最终通过当前游戏组件导出和路径核实。

已有任务目录覆盖广播、雷达、科研站、SEAF设施、机器人设施、虫族巢穴/TCS及光能者设施。另检查所有当前可标记且含任务交互/撤离组件的目录外实体：排除训练终端；地狱火、炸药、武器背包保留战备分类；通用任务代理不能凭组件猜具体建筑。货运车和机械虫洞有可复核路径，补入目录。

## 非投掷战备成功记录

游戏DLL指纹继续限制为Steam build 25480438。仅使用受保护读取，不写原生内存、不通过采样发送聊天。

- `game.dll+347CE50` 指向每人战备记录：记录步长`1690`，peer位于`+0`，条目位于`+1C0`、步长`30`，数量位于`+7C0`；管理器记录数位于`+2D200`。
- 当前成功函数`135C5D0`在成功分支写入条目`+10`开始时间和`+20`成功激活时间；后者可包含未来投放延时。固定三处指令签名，签名改变只禁用此读取器。
- 冷却函数`135C2C0`也会改变开始时间/冷却，且可能镜像其他队员记录。因此仅输入指令、失败、冷却改变不能算成功；要求成功激活时间增加，并检查游戏时钟的新鲜度。
- 刚解锁的任务条目，只有成功开始晚于上一游戏快照才接受。进入会话、切世界、人员变化、记录更换及游戏时钟倒退建立基线，历史旗帜不会补发。
- StratagemInfo在当前游戏只要求4字节对齐；已通过真实读取发现并回归此校验。按稳定ID识别，重新验证动态type和call type，不把易漂移枚举当固定身份。
- [task-stratagems.json](task-stratagems.json)记录22项已核实的非投掷调用及payload依据，含旗帜、钻机、数据上传、燃料提取和重新武装等；训练调用排除。资料来自当前[StratagemInfo导出](https://github.com/Darctor/Helldivers2_RawData/blob/main/Data/settings/generated_stratagem_settings.json)。

外部只读运行当前读取器已确认可建立任务战备基线，未产生历史事件；没有在游戏中远程执行函数或注入测试消息。离线预览已检查三个消息字段、开关和变量提示完整在框内。

新增发送效果仍需加载0.7.8后在游戏中验收，不能把离线回放或可读基线当作所有目标均实战通过。
