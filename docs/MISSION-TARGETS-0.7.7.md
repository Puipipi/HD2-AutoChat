# AutoChat 0.7.7 — 任务地点与任务交互物

## 识别范围

本版系统核对任务目标目录，而不是只补旗杆。`任务建筑`开关负责现场任务建筑、终端和任务携带物；地图任务/撤离区仍由地图开关负责。

210个当前可标记资源：174个有具体资源名；36个只能确认任务终端或交互物，显示“任务终端”或“任务交互物”，不猜任务名字。数量包含同一建筑的不同资源版本，不代表210种任务，也不代表所有条目都完成了实机标记测试。

## 名称规则

1. 游戏给出具体标记名时保留该名字。
2. 若只有通用key `3585962803`（当前中文“特殊地点”）、`4234884333`（“终端”）、`689074879`（“敌方单位”）或没有可读名称，使用已核对的实体资源名；资源本身有具体本地化key时优先读取游戏本地化，再使用目录兜底。
3. kind 0 不再一概当作空地：有已核对任务目标实体时发送具体目标；没有有效目标ID或不属于任务目录时仍忽略。
4. 地图 type 1 任务继续从当局对象读取任务名称与主线/前置/支线/战术属性，type 6显示撤离区。空白type 7仍忽略；不根据名字推断主线/支线，不根据最近坐标猜任务。

目录描述物体，地图描述任务。比如“非法广播塔”是现场物体，而“关停非法广播”是当局地图任务名。现场ping只剩通用地点且没有目标ID时，仍不能确认具体建筑；这不是给空点匹配一个邻近任务的依据。

## 来源与可复核事实

当前目录基于 `game_version=1.007.100 / patch_date=2026-09-22` 的组件导出，运行时仍由现有Steam build 25480438/DLL指纹检查限制。每项均有当前 `SpottableComponentData` 成员资格；已知路径通过 MurmurHash64A seed 0复算为目标64位资源ID。

- [EntityComponentMap](https://github.com/Darctor/Helldivers2_RawData/blob/main/Data/settings/EntityComponentMap.json)：当前实体、可标记成员资格与任务交互组件。
- [EncyclopediaEntryComponentData](https://github.com/Darctor/Helldivers2_RawData/blob/main/Data/entities/EncyclopediaEntryComponentData.json)：资源的本地化名称key。
- [FileDiver资源路径](https://github.com/xypwn/filediver/blob/master/hashes/hashes.txt)：具体实体路径，区分建筑、地图定义、武器和普通资源。
- [Wiki任务目录](https://helldivers.wiki.gg/wiki/Objectives)、[战术任务列表](https://helldivers.wiki.gg/wiki/Template:Tactical_Objective_Table)：辅助核对玩家可见任务类别。网页直读返回403，仅参考搜索摘要；未据此编造原生ID或字段偏移。

本轮另以外部只读方式读取运行中游戏的实际本地化表，核对了“终端”“中继塔”“地对空导弹发射器”“指挥碉堡”“发射代码”“超级固态硬盘”“幼虫储存器”“核导弹”“孢肺”“机器人的迫击炮台”“防空炮台”等文本。此过程只做ReadProcessMemory，不写游戏内存、不远程执行游戏函数、不发送测试聊天。
另从当前DLL `13D172E–13D173B` 确认未命名标记使用 `330A0E0[kind]`，只读该表并解析本地化：敌人式kind 1–8共享“敌方单位”，任务kind 18/19等共享“特殊地点”。这解释了为什么任务建筑不能仅依赖原生泛称。新回归先复现孢子目标被显示成“敌方单位”，再确认其资源具体名。另核实孢肺、机器人迫击炮和防空炮阵地的实际可标记实体；三项先复现不触发，再补入目录。迫击炮的地图任务定义本身不带可标记组件，现场读取使用炮台实体，避免混用地图定义ID。

完整可审查目录在 [mission-targets.json](mission-targets.json)，包含资源ID、已知路径、显示兜底、本地化key、具体/通用标识、组件事实与原始来源SHA256。未解出路径的项目明确保存 `path=null`。目录中的中文路径兜底不是全部游戏官方译名；可读的游戏具体名称优先。

更新目录后运行 `python -B tools/generate_mission_targets.py` 生成读取表，再同步内嵌片段。`--check` 和构建门禁检查目录与实际打包代码一致，避免以后只更新说明而漏改模组。

## 验证边界

先复现14类任务目标只显示“特殊地点”、地面式真实任务标记被误过滤，再修改读取。回归覆盖整个210项目录、通用终端名替换、具体原生名称优先、本地化key查询、资源路径哈希、CQC-1/地狱火/普通物资排除、真实读取到自动发送队列，以及既有地图任务与空点过滤。

新增目标的端到端聊天效果需要重启新版后实机验收；离线测试和本地化采样不能代替逐项实战测试。
